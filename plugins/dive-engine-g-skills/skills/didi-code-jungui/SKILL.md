# Didi Code Jungui（中文）

## 概述

本 skill 用于在编码、改码、重构、评审、配置和自动化任务中，强制执行滴滴在国际化、CAC、防腐边界、Elvish 时间与货币合规方面的军规。  
军规是硬约束：需求冲突时，必须调整方案，不得输出违规代码。

## 触发条件

当任务涉及以下任一主题时，必须先启用本 skill 并执行合规审视：

- 国家、城市、产品线、语言、locale、品牌、usertype
- IP、域名、机房差异、InRouterIP、部署环境、CAC 配置
- 时间存储、时间展示、跨天计算、时区、夏令时、定时任务
- 货币文案、金额存储、金额计算、汇率、币种、展示格式

## 强制规则

1. 禁止通过硬编码或业务分支表达国家、城市、产品线、语言、locale、机房、IP、时区、货币等差异。  
2. 禁止通过字符串拼接、截取、别名替换、隐式转换等方式绕过扫描规则。  
3. 差异化能力必须优先接入平台能力：  
   - Signpost / Apollo：放量和配置管理  
   - Fission SDK：国家、产品线等元数据  
   - DiRPC：下游调用  
   - CAC：机房差异配置  
   - Elvish：时间和货币处理  
4. 遇到时间和货币场景，默认认为手写原生逻辑不可靠，优先改用 Elvish。  
5. 若存在确实无法规避的场景，只能明确提示“需要申请例外”，不得输出临时绕过方案。

## 执行流程

1. 先识别是否命中触发条件。  
2. 命中后先做军规审查，再给方案或代码。  
3. 若命中红线，立即停止沿用原方案并改造为平台能力接入方案。  
4. 输出前执行“交付检查清单”。

## 交付检查清单

- 是否存在国家、城市、产品线、语言、locale 的硬编码或判断
- 是否存在 IP、机房域名、InRouterIP、机房关键词
- 是否把配置差异写入代码，而不是 CAC / Apollo / Signpost
- 是否存在跨天秒数运算、字符串时间处理、歧义时区
- 是否存在手工货币拼接、客户端货币文案、金额精度损失

命中任意一项时，不得继续沿用原方案。

## 输出要求

- 评审结论应先列风险点与命中规则，再给出合规替代方案。  
- 若需例外，必须明确写出风险点、命中规则，并建议通过 IBT 代码规范客服群申请跳过。
- 结束时要明确说明：按照 `didi-code-jungui` 技能完成执行。
